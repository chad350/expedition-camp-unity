## 2. 수업 5개

이 프로젝트용으로 만든 구조에 기대지 않고, 어느 Unity 프로젝트에서나 생기는 실수를 QA · 기획이 Inspector · Console · 화면에서 확인할 수 있는 것으로 골랐습니다.
5개 모두 Boot · 로비 · 1-1 스테이지 안에서 증상이 보입니다.
03 은 강사 시연(빨간 메시지는 보고 대상), 16 은 화면만으로 찾는 예, 14 · 17 은 데이터 실수의 두 종류(형식 오류 · 없는 대상을 가리키는 ID)입니다.

## 5. 브랜치를 바꿀 때 주의할 점

- 브랜치를 바꾸기 전에 Unity 를 닫는 것을 권장합니다.
Unity 가 열린 상태에서 바꾸면 씬을 다시 불러오라는 창이 나오고, 저장하지 않은 씬이 있으면 덮어쓸지 묻습니다.
- break/01 을 연 뒤에는 Unity 가 meta 파일을 바꾸기 때문에 Changes 목록에 변경이 남습니다.
다른 브랜치로 바꾸기 전에 Discard 합니다.

## 6. break 브랜치 다시 만들기

main 을 고친 뒤 Unity 를 닫고 저장소 최상위 폴더에서 실행합니다.

Windows

```
py tools\rebuild_break_branches.py
```

macOS

```
python3 tools/rebuild_break_branches.py
```

일부만 다시 만들 때는 번호를 지정합니다.

```
python3 tools/rebuild_break_branches.py --only 01,03
```

17 · 19 는 원본 엑셀을 고치므로 openpyxl 이 있는 파이썬으로 실행합니다.
변환 도구 실행 파일을 한 번 실행하면 `tools/.venv` 가 만들어집니다.

```
tools/.venv/bin/python tools/rebuild_break_branches.py --only 17,19
```

- 커밋하지 않은 변경이 있으면 실행하지 않습니다.
- 기존 break 브랜치는 main 의 최신 커밋에서 새로 만들어 덮어씁니다.
- Unity 로 적용하는 실수는 `tools/break/BreakApplier.cs` 를 잠시 `Assets/Editor/BreakTemp/` 에 복사해서 실행하고, 실행이 끝나면 지웁니다.
